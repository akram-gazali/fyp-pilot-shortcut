# SIFT-VQA pilot

Pilot pipeline for shortcut-aware example selection in VQA on synthetic 2D scenes.
All pilot defaults live in `configs/` (not final until the protocol lock). Every run writes
`run_meta.json` (config + git commit) next to its outputs. All numbers in `reports/` are produced by code.

## Setup
```bash
python3.12 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/pytest
```

## Reproduce Stages 1-3 (CPU, local, ~10 minutes; `data/` is git-ignored except small manifests)
```bash
.venv/bin/python scripts/gen_pool.py              # Stage 1: scenes, questions, pixel-based label audit
.venv/bin/python scripts/answer_stats.py data/pool/questions.jsonl reports/answer_stats_tuned.json
.venv/bin/python scripts/score_pool.py            # Stage 2: shortcut answers, d flag, disagreement report
.venv/bin/python scripts/make_stage2_summary.py   # reports/stage2_summary.md
.venv/bin/python scripts/build_splits.py          # Stage 3: splits, held-out signature, leakage checks
.venv/bin/python scripts/build_edits.py           # Stage 3: paired relevant/irrelevant test edits (~6 min)
.venv/bin/python scripts/run_selectors.py         # Stage 3: four selectors x 3 seeds x both exists modes
.venv/bin/python scripts/make_stage3_summary.py   # reports/stage3_summary.md
```
## Stage 4/5 (GPU needed; Kaggle first, Colab as fallback) and the final report
Kaggle: `kaggle/KAGGLE_STEPS.md` (notebook `kaggle/stage5_kaggle.ipynb`, runs top to bottom with "Save & Run All").
Colab: `colab/COLAB_STEPS.md`. Both notebooks are generated by `scripts/make_colab_notebook.py` (do not edit by hand; Colab's
"Save a copy to GitHub" overwrites the generated notebook, so do not use it). The GPU script is `colab/stage4_feasibility.py` (works on both):
```bash
python scripts/install_pinned.py                  # pinned non-torch packages (requirements-gpu.txt); never touches torch
python colab/stage4_feasibility.py check-env      # versions; fails if a pinned package differs
python colab/stage4_feasibility.py prepare        # rebuild data on CPU, check hashes against data/manifests
python colab/stage4_feasibility.py dev-format     # answer format + resolution chosen on the DEV set (train split)
python colab/stage4_feasibility.py zero-shot      # frozen reference on the test set with the chosen method
python colab/stage4_feasibility.py grid           # memory/speed grid; grid.json written row by row by the script
python colab/stage4_feasibility.py cost           # GPU-hour extrapolation (also keeps the Stage 4 scenarios for comparison)
python colab/stage4_feasibility.py tiny-finetune  # OPTIONAL, never run on a GPU yet
```
Copy the result JSON files into `reports/stage5/`, then locally (CPU):
```bash
.venv/bin/python scripts/power_calc.py            # held-out test-size proposal
.venv/bin/python scripts/make_stage4_summary.py   # reports/stage4_summary.md (Stage 4 files)
.venv/bin/python scripts/make_pilot_report.py     # reports/pilot_report.md (reads only the JSON files)
```
### Answer format (Stage 5)
Stage 4 scored `0` / `Yes, 1` answers to yes/no questions as wrong. Stage 5 compares, on the dev set (the train split, never the test set):
(1) a per-template instruction suffix with greedy generation, (2) choice scoring (log-probability of each candidate answer, no generation),
and the old one-size suffix as a diagnostic. Rule (fixed before the run): highest dev macro accuracy; within 1 point counts as a tie and the faster
method wins. The resolution is 224 px unless 336 px is better by more than 2 macro-accuracy points. The choice is written to `eval_choice.json` and the
**same method is applied to every arm**; the section of `reports/pilot_report.md` titled "Answer-format study" records the result and the reason
(not filled until the GPU run). The dev set has no compare_cs questions (ASSUMED to behave like the other yes/no templates).
Status: Stage 4 zero-shot (old format) and a hand-transcribed Stage 4 grid are in `reports/stage4/`; the Stage 5 GPU results are pending.
GPU code paths are CPU-tested only (`tests/test_stage5*.py`); the tiny fine-tune has never run on a GPU.

Optional: `scripts/tune_generator.py` (generator tuning on separate seeds, no rendering).

## Layout
`src/siftvqa/` library (dsl, executor, scene, templates, audit, shortcuts, splits, leakage, edits, selectors),
`configs/` (generator, shortcuts [frozen, hashed], splits, selection), `scripts/` (one CLI per step),
`tests/`, `reports/`, `data/manifests/` (small tracked manifests with config and shortcut-file hashes).
